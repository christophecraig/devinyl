# Test audio fixtures (task 1.29)

All files here are **synthesized tones** generated by
`scripts/make-fixtures.mjs` — there is no copyrighted audio in this repo.
Regenerate with:

```sh
node scripts/make-fixtures.mjs
```

## Format

Plain **PCM WAV** (44-byte RIFF header + 16-bit mono samples), hand-written by
the generator script — no `ffmpeg`/`lame` dependency. Deezer serves MP3
previews, but `AudioContext.decodeAudioData` decodes WAV natively, so these
are a fine stand-in wherever a test needs _a_ clip rather than specifically an
MP3. Sample rate is 11 025 Hz, which lands a 30 s tone close to the ~480 KB/clip
estimate the preloader budgets against (technical-spec §4).

## Files

| File                      | Purpose                                                                                                                                                                                                  |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tone-a-440hz-30s.wav`    | 440 Hz tone, ~30 s. Standard-length fixture.                                                                                                                                                             |
| `tone-b-880hz-30s.wav`    | 880 Hz tone, ~30 s. A second, distinguishable clip — pick by ear/spectrum in tests that need to tell two rounds apart.                                                                                   |
| `tone-c-220hz-30s.wav`    | 220 Hz tone, ~30 s. A third, distinguishable clip.                                                                                                                                                       |
| `tone-short-660hz-5s.wav` | 660 Hz tone, ~5 s. Deliberately **not** 30 s — proves the scoring curve divides by the buffer's _measured_ duration (`audioBuffer.duration * 1000`) rather than an assumed 30 000 ms (§9).               |
| `corrupt.wav`             | A `RIFF`/`WAVE` header followed by garbage instead of a real `fmt `/`data` chunk. `decodeAudioData` must reject it — this exercises the preloader's decode-failure → retry → skipped-round path (MUS-5). |

Each tone has a 20 ms linear fade in/out so decoders never trip on a
hard-edged sample-0 discontinuity.
